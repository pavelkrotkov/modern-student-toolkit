# Шпаргалка: Git

Используй после [урока 7](../06-git-github.md), где настроены имя и почта автора. Здесь пример для существующего `Codex-Practice` и файла `one.txt`.

## Обычный цикл

```bash
cd ~/University/Projects/Codex-Practice
git status
git diff -- one.txt
git add one.txt
git diff --staged
git commit -m "Пояснение к моему изменению"
git push
```

Выполняй построчно и меняй пояснение к коммиту. `git push` нужен только при настроенной удалённой копии. Обычный `git diff` не показывает новые неотслеживаемые файлы; подготовленные изменения видны с `--staged`.

## История и восстановление

`git log --oneline` показывает краткую историю. **q** закрывает просмотрщик, если он открылся.

`git restore -- one.txt` возвращает файл к подготовленному состоянию, а если подготовленных изменений нет — к последнему коммиту. **Несохранённые изменения этого файла пропадут.** Сначала посмотри разницу и скопируй нужный текст. Для упражнения используй только пробное изменение из урока.

## Копия готового репозитория

```bash
cd ~/University/Projects
git clone https://github.com/pavelkrotkov/modern-student-toolkit.git
```

Повторно поверх существующей папки клонировать не нужно. `git pull` получает изменения из удалённой копии текущего репозитория. При конфликте остановись и используй [помощь](../help.md).

## Новый репозиторий

Проверь `pwd` перед `git init -b main`. Инициализируй только папку конкретного проекта. Для создания закрытой удалённой копии после первого коммита и `gh auth login`:

```bash
gh repo create ИМЯ --private --source=. --remote=origin --push
```

Замени `ИМЯ` на свободное имя репозитория. Проверяй пометку **Private** на GitHub.
