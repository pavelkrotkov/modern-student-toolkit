# 7. Git и GitHub: сохрани и восстанови версии

**Время:** 60–90 минут; можно разделить на локальную и сетевую части. **Результат:** два сохранённых состояния учебных файлов и их копия в закрытом репозитории GitHub.

## Перед началом

Пройдены уроки 0–6. Работают `git --version` и `gh --version` из урока 5. Есть `~/University/Projects/Codex-Practice/one.txt` и `two.txt`. Если Git установить не удалось, вернись к условиям урока 5; выполнять следующие команды пока не получится.

**Git** хранит историю файлов. **Репозиторий** — проект с такой историей. **GitHub** — сайт, где можно хранить удалённую копию репозитория. Для первых локальных действий интернет не нужен.

## 1. Настрой автора коммитов

**Коммит (commit)** — сохранённое состояние выбранных файлов с пояснением. В нём записываются имя и почта автора. Вход в GitHub не настраивает их автоматически.

Если GitHub разрешён и доступен, создай учётную запись на <https://github.com/>. В её настройках включи двухфакторную проверку входа и сохрани коды восстановления в своём менеджере паролей. Если хочешь скрыть почту, в **Settings → Emails** включи **Keep my email addresses private** и скопируй предоставленный адрес `noreply`.

Сначала посмотри текущие настройки:

```bash
git config --global user.name
git config --global user.email
```

Пустой вывод означает, что значение ещё не задано. Если уже указаны подходящие имя и почта, оставь их. Иначе в следующих командах **замени оба значения внутри кавычек своими**. Для имени можно использовать псевдоним. Не вставляй пример адреса буквально:

```bash
git config --global user.name "Твоё имя или псевдоним"
git config --global user.email "Твой адрес для коммитов"
```

`--global` применяет настройку к репозиториям твоей учётной записи на Mac. После изменения проверь:

```bash
git config --global user.name
git config --global user.email
```

Здесь должны появиться выбранные значения, а не текст заготовки. Для локальной части можно использовать собственную почту; она попадёт в историю, если позднее отправить её на сервер.

**Проверено: 2026-10-07.** [Имя автора](https://docs.github.com/en/get-started/git-basics/setting-your-username-in-git), [почта и noreply](https://docs.github.com/en/account-and-profile/how-tos/email-preferences/setting-your-commit-email-address).

## 2. Создай историю учебной папки

Выполняй по одной строке:

```bash
cd ~/University/Projects/Codex-Practice
pwd
git init -b main
git status
```

Проверь путь **до `git init`**: он должен заканчиваться на `/Projects/Codex-Practice`. Не выполняй `git init` в `University` целиком. `main` — имя основной **ветки**, то есть линии истории проекта.

`git status` покажет новые файлы как `Untracked files`: Git видит их, но ещё не хранит. Подготовь только два учебных файла:

```bash
git add one.txt two.txt
git diff --staged
```

`git add` выбирает содержимое для следующего коммита и помещает его в **область подготовки (staging area, или index)**. `git diff --staged` показывает именно подготовленные изменения. Строки с `+` добавляются. Если открылся просмотрщик, нажми **q**, чтобы выйти.

```bash
git commit -m "Добавлены первые учебные файлы"
git log --oneline
```

`-m` задаёт пояснение. В истории должна быть одна запись. Остальные файлы папки могут остаться `Untracked` — это нормально. Git не сохраняет пустые папки вроде `archive`.

## 3. Посмотри изменение и отмени его

Открой `one.txt` в TextEdit, допиши строку `Пробное изменение для отмены.` и сохрани. Затем:

```bash
git diff -- one.txt
```

Это разница между рабочим файлом и подготовленным состоянием. Ты должен увидеть добавленную строку. Чтобы вернуть **только `one.txt`** к сохранённому состоянию, выполни:

```bash
git restore -- one.txt
cat one.txt
```

По умолчанию `git restore -- one.txt` берёт содержимое из **области подготовки**, а не обязательно из последнего коммита. В нашем упражнении они совпадают: после коммита мы ещё не выполняли `git add` для пробной строки. Если сначала подготовить новое содержимое через `git add`, эта команда вернёт именно его.

**Команда заменяет рабочее содержимое выбранного файла; изменения, которых нет в области подготовки, пропадут.** Здесь это именно пробная строка, которую мы решили отменить. Прежде чем применять команду к настоящей работе, просмотри разницу и сохрани нужный текст отдельно.

Строка о пробном изменении должна исчезнуть; первоначальный текст — остаться.

## 4. Сохрани вторую версию

Снова открой `one.txt`, добавь `Я умею проверять и сохранять изменения.` и сохрани файл.

```bash
git diff -- one.txt
git add one.txt
git diff --staged
git commit -m "Добавлено умение сохранять версии"
git log --oneline
```

Теперь в истории две записи. После `git add` обычный `git diff` может ничего не показывать: изменения уже подготовлены. Для них используется `--staged`. Совсем новые файлы тоже не видны в обычном `git diff`; сначала посмотри `git status`, затем добавь нужный файл и проверь `--staged`.

## 5. Отправь закрытую копию на GitHub

```bash
gh auth login
```

Выбери **GitHub.com**, **HTTPS**, вход через браузер. Если спросит, использовать ли эту учётную запись для операций Git, согласись. Код входа вводи только на странице GitHub, которую открыл этот процесс; не отправляй его в чат.

```bash
gh auth status
```

Если вход успешен и имя `codex-practice` свободно в твоей учётной записи:

```bash
gh repo create codex-practice --private --source=. --remote=origin --push
```

`--private` создаёт закрытый репозиторий; `origin` — короткое имя удалённой копии; `--push` отправляет коммиты. Если репозиторий уже существует, не удаляй его: используй [помощь](help.md).

Открой GitHub в браузере, найди репозиторий и проверь пометку **Private**, оба текстовых файла и две записи истории. Закрытый репозиторий хранится на внешнем сервисе; не помещай туда пароли и чужие личные данные.

Для последующих изменений: просмотр → `git add ИМЯ_ФАЙЛА` → просмотр `--staged` → коммит → `git push`. `ИМЯ_ФАЙЛА` нужно заменить настоящим именем. `git pull` получает изменения с сервера; при сообщении о конфликте остановись, не используй принудительную отправку.

Если GitHub пока недоступен, локальные коммиты и восстановление продолжают работать. Отметь сетевой шаг как отложенный.

## 6. Скачай исходные файлы курса

**Клонирование (clone)** создаёт локальную копию существующего репозитория. Теперь скачивание курса имеет понятную цель: получить учебную программу и дополнительные материалы.

```bash
cd ~/University/Projects
git clone https://github.com/pavelkrotkov/modern-student-toolkit.git
cd modern-student-toolkit
git status
ls
```

Если папка уже существует, сначала выясни, откуда она появилась; не клонируй повторно поверх неё. **Корень репозитория** — папка `modern-student-toolkit`, где находятся `README.md`, `docs`, `Brewfile` и скрытая служебная папка `.git`. `ls -a` показывает также скрытые имена.

Это отдельный репозиторий, не продолжение `Codex-Practice`. Учебные исходники курса здесь не редактируй; для работы будем копировать нужные файлы. [Клонирование](https://docs.github.com/en/repositories/creating-and-managing-repositories/cloning-a-repository), [создание репозитория через gh](https://cli.github.com/manual/gh_repo_create).

## Дополнительно: история заметок {#notes-git}

Это можно сделать после основного маршрута, если в уроке 3 создана папка `Notes/Courses` с заметками. Сначала создай резервную копию важных заметок. Затем открой в Terminal только `~/University/Notes`, проверь `pwd`, выполни `git init -b main`.

Перед первым добавлением файлов создай `.gitignore` — список исключений из Git. Посмотри `ls -a`: если такой файл уже есть, прочитай его через `cat .gitignore` и не перезаписывай. Только если файла нет, выполни:

```bash
printf '%s\n' '.DS_Store' '.obsidian/' > .gitignore
cat .gitignore
```

`printf` печатает строки, а `>` записывает их в файл, **заменяя прежнее содержимое**, если файл существует. Здесь исключены служебные настройки Obsidian. После проверки списка заметок выполни `git add .gitignore Courses`, `git diff --staged` и коммит с собственным пояснением. Для закрытой копии можно использовать `gh repo create university-notes --private --source=. --remote=origin --push` после входа в GitHub.

GitHub хранит историю отправленных файлов; это не полная резервная копия Mac и не автоматическая синхронизация Obsidian. Автоматический плагин разумно подключать после нескольких ручных сохранений.
