# Работа над курсом

Этот файл предназначен для автора. Ученик начинает с публичного сайта, установка MkDocs ему не нужна.

## Локальный просмотр и проверки

Все служебные файлы держите внутри папки проекта. Пример для macOS/Linux:

```bash
mkdir -p .cache/tmp .cache/pip
python3 -m venv .venv
TMPDIR="$PWD/.cache/tmp" .venv/bin/python -m pip install --cache-dir .cache/pip -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/mkdocs build --strict
TMPDIR="$PWD/.cache/tmp" .venv/bin/mkdocs serve
```

Откройте <http://127.0.0.1:8000>. `.venv`, `.cache` и `site` исключены из Git. Проверки Python выполняются стандартной библиотекой; дополнительные зависимости нужны только сайту.

## Публикация

PR проверяется автоматически. Публикация GitHub Pages происходит после попадания изменений в `main`. Проверяйте итоговый diff и результаты проверок перед объединением. Скрипт `scripts/publish.sh` предназначен для первоначального развёртывания; для обычной правки курса он не нужен.

Существующие имена файлов уроков сохранены ради опубликованных адресов. Текущий порядок и номера определяются заголовками, ссылками «Дальше» и `mkdocs.yml`.

## Проверка учебного маршрута

- В каждом занятии есть цель, время, предварительные требования, проверка результата и самостоятельная попытка.
- До Git-урока все учебные материалы доступны по прямым ссылкам с сайта.
- Программа устанавливается перед первым применением. Необязательные средства не блокируют маршрут.
- Каждая команда опирается на уже созданную папку и объяснённое понятие.
- Результаты совпадают между источниками поездки, CSV, таблицей и Python. При изменении данных обновляйте контрольные числа и проверки.
- Просмотрены страницы с таблицами, кодом, раскрывающимися ответами и ссылками загрузки.
- Проверены русский язык, точные имена файлов и варианты локализованного интерфейса.
- Меняющиеся инструкции сверены с первичными источниками и датированы. Загрузка приложения не гарантирует доступность всех функций учётной записи.

## Как улучшать по обратной связи

После реального прохождения соберите: номер урока и шага, время, ожидаемый и фактический результат, уровень помощи. Не публикуйте личные данные ученика или содержимое его учебных аккаунтов.

Сначала исправляйте шаги, где ученик остановился. Затем уточняйте объяснения и время. Если ученик выполнил задачу только с ИИ, предложите похожую самостоятельную задачу и повторите её через неделю. Данные нескольких учеников помогают улучшить курс, но не доказывают общую эффективность обучения.

Для небольшой обратной связи достаточно отдельного исправления в PR. Самостоятельное обсуждение или крупную новую тему удобно оформить issue. Не нужно заранее создавать список задач на каждое возможное улучшение.
